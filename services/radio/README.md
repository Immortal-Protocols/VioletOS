# Radio service

[Settings › Wi-Fi](../../apps/open/settings/src/wifi.rs) scans the QEMU network profiles and select one by stable ID. By default there are two open networks and **VIOLET HOME**, a WPA2 network with the password `violet-home`. Set `VIOLET_NETWORKS='["VIOLET LAB",{"name":"HOME","password":"12345678"}]'` to change them. They are virtual access points sharing one Ethernet uplink; a WPA2 one accepts a join only with the right key.

A join (`EXECUTE PROFILE`) can carry the network's WPA2 key in its data. Radio keeps it for the boot, uses it in place of a USB-provisioned profile with that name, and answers a failed join with the reason (`JOIN_*` in [protocol.rs](../../runtime/protocol.rs)), for example 52 when the access point refused the handshake (a wrong key) and 57 when it did not finish for another reason (no answer, a lost frame), which must not cost a saved key. On the Moto, Radio controls the physical Wi-Fi chip and joins a provisioned WPA2 network. [USB Diagnostics](../usb-diagnostics/README.md) exposes its status and forwards scan and join requests from the Mac.

**Test Radio** sends an ARP request to the QEMU gateway. It then opens a TCP stream through the emulator’s [relay](../../tools/emulator_endpoint.py). Inside the guest, the [TLS client](tls.c) draws entropy from virtio-rng, checks the certificate chain, hostname and QEMU clock, and fetches the response over HTTP/1.1. The guest accepts a UUIDv4 from the fixed endpoint and shows it on screen. The client speaks TLS 1.2 with ECDHE and AES-128-GCM only (ECDSA or RSA certificates), and only those algorithms are linked into Radio; `make test-radio-tls` checks the client against a local server (both suites fetch the page; other suites, a wrong name and an unknown root are refused). The image ships the ISRG Root X1 trust anchor. Changes to the endpoint’s trust chain can require a radio package update. [Endpoint](https://www.uuidgenerator.net/api/version4)

Run `make test-wifi` for network selection, persistence, link failures, rejection of plaintext, and app switching during a delayed request. Run `make test-wifi-live` for the public endpoint.

## Open apps' sockets

On the Moto, Radio also serves the open apps' TCP and UDP sockets from its event loop ([sockets.c](../../targets/moto-g-pure/ip/sockets.c)), through 32 slots in pages shared with the Open Runtime ([net.rs](../../runtime/open/net.rs) has the layout and [slots.rs](../../runtime/open/slots.rs) the per-app shares). Nothing in that code waits: each connect is a small state machine (resolve the name, connect, then the SOCKS handshake in Phone Internet mode) stepped once per pass with a deadline per step, so one app's connect to a host that does not answer no longer stalls every other socket, Bluetooth and Radio's requests for up to 13 seconds. Received bytes are copied into the socket's ring as they arrive, so a socket whose app is not reading holds none of lwIP's packet buffers, and each sending socket may queue only its share of half of lwIP's 24 KiB heap. Radio is the only writer of its side of a slot's rings and empties them when it takes a command, after it has let go of the slot's previous connection, so a slot the Open Runtime reused before Radio saw the close cannot hand the old connection's bytes to the new one. A closed connection waits in lwIP at the lowest priority, where lwIP takes it back for the next connect that finds none of its 40 free. lwIP cannot be told to forget a name it is asking for, so Radio counts those questions by app (the Open Runtime writes whose socket a slot is): 4 for one app, 32 for all apps, 4 for the runtime's own sockets, of the 40 lwIP holds. A name that is an IPv4 address written out is refused, not resolved. Radio serves only the slots whose rings the supervisor says it mapped (word 5 of the first page); under a supervisor from before that word it serves the 7 slots that fit the 49 pages those mapped. Radio's own HTTPS test still runs to completion inside the loop.

`make test-unit` runs the real sockets.c on the host against a stand-in for lwIP ([test_sockets.c](../../targets/moto-g-pure/ip/test/test_sockets.c)): a connect that never answers beside a slot that keeps talking, names answered late or never, the relay's replies a byte at a time, window and heap accounting, a slot reused while its old connection is still receiving, an app that opens and closes connections against a server that never closes, one that asks for names nobody answers, and a supervisor that mapped less. `make test-net-lwip` (local: it needs lwIP's source, which the image build downloads) runs the same file against lwIP itself with Radio's options and a peer played by hand ([test_lwip.c](../../targets/moto-g-pure/ip/test/real/test_lwip.c)). Neither is a phone: sockets.c has not been run on a handset since this rewrite, which needs a handset build and a network; Radio's own HTTPS test still blocks the loop while it runs; and out-of-order TCP segments are still queued by lwIP on the connection, not in the slot's ring. In QEMU the Mac serves the same pages ([net_relay.py](../../tools/net_relay.py)).
