# Process supervisor

The [shared Moto and QEMU first task](supervisor.c) constructs address spaces, threads and endpoint permissions. It starts the launcher, Runtime and services, opens apps on demand, and reinitializes private execution state on Quit. Each Runtime worker can contact its assigned service. Only Display and the Open Runtime hold the scanout mapping; the Open Runtime draws only while Runtime has given it the screen.

The supervisor receives kernel fault messages and monitors in-flight service calls. Runtime and the foreground app also have progress deadlines. After a fault or a 20-second stall it restarts the managed group. A guest-installed catalog that fails during its trial (from its commit until it has run healthy for 20 seconds) is retired on disk and the previous catalog runs; one that has passed its trial, or was found at power-on, is restarted as it is, so a crash cannot bring back older packages ([details](../package-manager/README.md#signatures-and-versions)). On QEMU a host-staged catalog falls back to the previous staged one at any time. Repeated failures during startup stop the recovery loop.

Before it runs any package the supervisor checks the package's publisher signature against the keys pinned in the boot image, and its security version against the version floors ([signatures and versions](../package-manager/README.md#signatures-and-versions)). A catalog with a package that fails either check is not booted.
